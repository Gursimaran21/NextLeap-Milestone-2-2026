## Milestone 2 - ChatGPT : Why Users are Not using Voice Input on ChatGPT Mobile, especially in India

### Solution to ChatGPT Problem Framing, Ideation & Validation + Metrics: Why Users are Not using Voice Input on ChatGPT Mobile, especially in India

#### Task 10 - Problem Framing Canvas

### Problem Framing Canvas — ChatGPT Mobile Voice Adoption in India

Based on the quantitative and qualitative evidence we've reviewed, I would use **Indian students aged 18–24 who frequently use ChatGPT on mobile but primarily type** as the target segment.

OpenAI's India data shows that 18–24-year-olds generate **just under half of ChatGPT messages in India**, while India has the largest student population on ChatGPT globally.

**1. Target User 👤**

**Who are we solving for?**

**Mobile-first Indian students aged 18–24 who frequently use ChatGPT for learning but rarely use Voice.**

Typical use cases:

- Exam preparation
- Understanding difficult concepts
- Homework/assignments
- Coding
- English/language learning
- Interview preparation
- Brainstorming

**Typical environment:**

Hostels, PGs, classrooms, libraries, homes and public transport.

**2. User Goal** 🎯

**"I want to interact with ChatGPT quickly and naturally when I'm learning, without spending unnecessary time typing."**

The ideal experience is:

**Ask → understand → follow up → practice → learn**

rather than:

**Type → submit → read → type again.**

Voice has particular potential for conversational learning, brainstorming and language practice.

**3. Current Behavior** 🔄

**What users do today**

Even when Voice is available, many users revert to this behavior.

**Why?**

Because typing feels:

- More predictable
- More private
- More controllable
- Easier to edit
- More appropriate for academic work

**4. Pain Points** 😣
   
🔴 **Accuracy / Trust**

**"Will ChatGPT understand my accent, Hinglish or technical terms?"**

Indian multilingual research has found ASR difficulties around Indian accents, Hindi loanwords, proper nouns and code-switching.

🔴 **Privacy**

**"I don't want people around me hearing my questions."**

Particularly relevant in hostels, classrooms, libraries and shared homes.

🟠 **Control**

**"With typing I can think, edit and correct my question before sending it."**

🟠 **Value**

**"Why should I speak when typing already works?"**

🟡 **Discoverability**

Some users don't notice or understand the Voice entry point.

**5. User Anxiety** 😰

The recurring anxieties can be summarized as:

| Anxiety         | User thought                             |
| --------------- | ---------------------------------------- |
| **Accuracy**    | "What if it misunderstands me?"          |
| **Language**    | "Will it understand Hinglish?"           |
| **Privacy**     | "Can someone hear me?"                   |
| **Social**      | "Will I look weird talking to my phone?" |
| **Control**     | "Can I correct what I said?"             |
| **Reliability** | "Will I have to repeat myself?"          |
| **Value**       | "Is this actually faster?"               |

**6. Mental Model** 🧠

This is arguably the **most important insight**.

**Non-regular Voice user**

**"Voice = another way to enter a prompt."**

Therefore:

**Typing**

= precise + editable + private + reliable

**Voice**

= fast + uncertain + public + harder to control

**Regular Voice user**

**"Voice = talking to ChatGPT."**

Therefore:

**Voice**

= conversation + brainstorming + follow-ups + natural interaction

This mental-model difference explains why simply improving the microphone button may not be sufficient.

**Primary root cause**

**Voice has not yet earned enough trust to overcome the perceived convenience and control of typing.**

**8. Why Existing Solutions Aren't Enough**

| Existing capability | Why it may not solve the problem            |
| ------------------- | ------------------------------------------- |
| 🎙️ Voice button    | Doesn't address trust                       |
| Speech recognition  | Accuracy varies by language/accent/context  |
| Voice conversation  | Doesn't solve privacy                       |
| Dictation           | Still feels like a typing replacement       |
| Multimodal input    | Doesn't create a Voice-first learning habit |

The product therefore needs to solve **behavioral friction**, not simply provide another input method.

**9. Opportunity**

**How Might We?**

**How might we make ChatGPT Voice feel as trustworthy, private and controllable as typing—while preserving the speed and conversational benefits of speaking?**

This opens four opportunity areas:

**① Linguistic trust**

Make Voice work naturally with:

- Indian accents
- Hinglish
- Regional languages
- Technical vocabulary
  
**② Contextual privacy**

Enable Voice to work better in environments where speaking is uncomfortable.

**③ User control**

Give users confidence that they can:

- Review
- Correct
- Interrupt
- Rephrase
- Switch between Voice and text

**④ Voice-first learning**

Create experiences where Voice is **meaningfully better than typing**, such as:

- Interactive tutoring
- Speaking practice
- Mock interviews
- Oral quizzes
- Brainstorming
- Socratic questioning

**10. Success Definition** 📈

Don't define success as:

❌ "**More users click the Voice button.**"

That's only activation.

Define success as:

More Indian students repeatedly choose Voice for relevant learning tasks.

**12. 🎯 Final problem statement**

**Indian students aged 18–24 don't reject ChatGPT Voice—they default to typing because Voice feels less linguistically reliable, socially comfortable, and controllable in their everyday learning contexts.**

**In 5 words:**

“**Voice hasn't earned enough trust.**”

That is the **core problem** I'd carry forward into the next PM stage: **solution ideation and prioritization**.
